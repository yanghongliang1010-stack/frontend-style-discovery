# Responding to feedback

| User feedback                                      | Preserve                                 | Next action                                                         | Avoid                                    |
| -------------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------- | ---------------------------------------- |
| “Find 10–20 pages for me to choose.”               | Product/task context                     | Search and present a varied numbered gallery                        | Another arbitrary redesign               |
| “I like 4, 9, 12.”                                 | Those sources                            | Extract supported properties; clarify the strongest unresolved axis | Assuming every layout/color was accepted |
| “I like the 3D materials; none of the workspaces.” | Materials and motion                     | Search scene-centered product UI and practical navigation           | Repeating rejected dashboards            |
| “Brighter, warmer, more contrast.”                 | Previously liked structure               | Revise light/palette and show the changed artifact                  | Resetting layout without reason          |
| “Everything is wrong.”                             | Explicit requirements, negative evidence | Change the structural hypothesis; search different references       | Recoloring the same grid                 |
| “Compact and keyboard-driven.”                     | Dense task focus                         | Explore lists, editors and commands                                 | Adding an immersive landing page         |
| “Use both, let users switch.”                      | Accepted variants                        | One component structure; coordinated themes and persistence         | Maintaining two separate apps            |
| “Design first, ignore old styling.”                | Functions and requested stage            | Complete design/prototype, integrate later                          | Premature backend or credential changes  |
| “Use this; now implement.”                         | Exact accepted version                   | Proceed within existing authorization                               | Reasking already-granted permission      |

For contradictions, assign roles before asking: “4 for reading order, 9 for material, 12 for color.” If those roles conflict, show two concrete alternatives or ask one property question. Do not average contradictory layouts into an incoherent UI.

Resume by reading the brief, latest manifest, exported choices and decision record. State the next unresolved point, preserve reference identities, and continue from the recorded stage.

An unavailable browser means no interaction claim. Missing image generation still permits research and an authorized HTML/CSS exploration. Missing tools should not trigger credential requests for work that does not need a model API.

Useful short questions: “Which part of 9: its layout, color, material, or interaction?” / “Should the workspace feel dense and quick, or open and spatial?” Ask only when the user's existing words do not already answer it.
