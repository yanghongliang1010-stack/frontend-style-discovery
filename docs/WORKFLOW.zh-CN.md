# 从模糊想法到可开发界面的操作流程

## 1. 从当前证据开始

读现有选择、草稿和功能边界。只需要产品、主任务、必要页面、设备和当前阶段；从已知信息补齐，不让表达不清的用户先填写设计问卷。

当前不知道风格就找案例；选了案例就提炼属性；认可了属性就出完整稿；只否定一部分就修订那部分；已经说“用这套开始做”就在授权范围内开发。

## 2. 准备 10–20 个有差异的真实参考

围绕主任务搜索作者原作和产品 UI，兼顾不同布局、密度、颜色、材质和交互。品牌展示站、登录后应用、静态设计图、原生空间概念必须分清。打开作者链接检查当前内容；浏览器能操作时再验证交互。

每项记录编号、作者、原作 URL、类型、适用部分、预览来源、核验状态和许可。编号稳定，跨轮次继续编号。不要用加载屏、空白画布或未看过的图片冒充预览。受限来源要明确只有链接，不能写成已验证。

公开仓库的 16 项来源库是研究入口，附带的两张 COMMONPLACE 图片是原创概念。针对真实任务重新选案例、核验并补充允许使用的本地预览，不要把这 16 个入口套给所有人。

## 3. 让用户轻松选择

生成本地选图册后，用户可以搜索、筛选、喜欢/不喜欢、写理由、放大、对比和导出。最简单的回复只是几个编号；备注不是必填。

```sh
python3 skills/frontend-style-discovery/scripts/build_gallery.py examples/demo.json --output out/gallery
python3 -m http.server 8780 --bind 127.0.0.1 --directory out/gallery
```

打开 http://127.0.0.1:8780/ 。工具只需 Python 3.10+，无需 Node、模型密钥或图片上传。浏览器中保存的选择有项目和来源身份校验；换浏览器/轮次前导出 JSON。来源、备注只在本地处理，原作链接在新标签打开。

## 4. 把反馈变成属性证据

分开记录布局、层级、密度/空间、字体、颜色/光线、材质/图像、交互/动态的保留、拒绝和待确定项。喜欢一个作品可以仅表示喜欢其材质。保留原话，不擅自推导“已定稿”。

```sh
python3 skills/frontend-style-discovery/scripts/summarize_choices.py examples/reference-library.json examples/walkthrough/choices.json --output out/preference-evidence.json
```

该文件是事实摘要，接受状态为空。助手仍需解释理由，只有必要时才问一个具体问题。

## 5. 围绕未决定的部分进入下一轮

准备同项目的新参考清单，新项使用全新编号。运行以下示例，自动固定喜欢的来源、携带原始反馈、保留历史编号，并复制相对预览路径：

```sh
python3 skills/frontend-style-discovery/scripts/advance_round.py examples/reference-library.json examples/walkthrough/additions.json --decisions examples/walkthrough/choices.json --output out/round-2
python3 skills/frontend-style-discovery/scripts/build_gallery.py out/round-2/references.json --output out/round-2-gallery
```

输出目录已存在时工具拒绝覆盖，换一个新目录或明确处理自己的旧产物。新图库中导入上一轮 JSON，会应用仍匹配的来源并说明未匹配项；项目错误、编号重复、来源被换掉和损坏数据会整体拒绝，避免部分更新。

## 6. 组合原创主视图

给来源分配角色，比如收藏阅读顺序、玻璃材质、快捷操作。先处理层级和密度冲突，再确定字体、色彩、间距、面板、动效和小屏行为。保持原创，不复制来源的品牌、作品或完整场景。

交付可辨认的完整主视图，不只交付一句风格描述。图像生成可用于视觉稿；没有生成工具时也能使用已经授权的 HTML/CSS 探索。状态和功能文字要留给可读、可交互的代码实现。

## 7. 精确修订并保存接受记录

“更暖”修改光线/颜色；“布局不对”修改结构；“全部不喜欢”回到参考或不同结构假设。不能把同一布局反复换色当成多轮探索。记录草稿版本、提示词和反馈。

接受两版作主题时统一布局、行为和组件，再协调主题 token。只在用户确实接受时填写原话、版本和开发范围。图库的喜欢按钮不是发布或开发审批。

## 8. 把定稿交给开发并验证

填写 `references/handoff-template.md`：必要页、准确文案、主任务、字体/间距/颜色、交互触发、空/加载/失败状态、响应式、持久化、接口及验收。

保留原项目的路由、权限、认证和业务契约。需要真实 3D 交互才接渲染器，并提供键盘/手机/渲染失败入口。用同尺寸浏览器截图与定稿比较，记录差异和修复；实际验证主任务、键盘、减少动态、三个宽度和主题刷新。

最后分开报告：概念图、本地原型、构建、浏览器、真实后端、真实用户。脚本演练不能称为用户研究，前端构建通过不能称为整体功能上线。

## 9. 跨项目复用和公开分享

安装后用 `$frontend-style-discovery` 触发，工具相对 SKILL.md 的目录定位，应用目录任意。公开时只带原创或获准再分发的资源、通用说明和原作链接；不要直接放入使用者的项目名称、截图、业务数据或私人对话。
