# 完整操作流程

## 1. 建立最小需求

确定产品、主任务、用户、设备、必要页面和当前阶段。用户已经说明“先设计、再连接功能”时，先把完整设计做出来。重做现有系统要记录功能边界，不把旧视觉限制带入新设计。

输出一份短需求记录；不要要求表达不清的用户先提供完整设计术语。

## 2. 找案例，让选择具体

初轮通常提供 10–20 个差异明显的真实参考。每个参考有稳定编号、作者、原作链接、类型、可学习的部分和核验情况。优先使用可辨认界面的实际预览。

作品网站、产品界面、设计截图与原生空间概念要明确标注。若作品只能查看公开静态图，就不要把动态交互写成已验证。访问受限时提供原作链接并说明限度。

本地清单使用 `schema_version: 1`、`project_id`、`round`、`references`。图片是清单目录内的本地文件；没有授权预览可省略 `image`，生成明确的原作链接卡片。

## 3. 生成选图册

运行 gallery builder，再启动本机静态服务。用户可以搜索、按方向筛选、喜欢／不喜欢、备注理由、放大、对比和导出。清单中的每个编号始终指向同一参考，新轮次继续编号。

选择数据保存在浏览器。导出文件可以跨浏览器和轮次传递；下一轮导入时只应用匹配的编号。备注不会自动上传，分享前应检查是否含有私密内容。

## 4. 提炼偏好，而不是猜全部

把反馈拆成布局、空间、密度、字体、配色与光线、材质、交互几条轴，分别记录喜欢、不喜欢和待确定。选择一个作品不等于接受它的全部界面。

例如：“主要喜欢 3D 场景和材质，工作区也想有空间感”，接下来应该找空间应用布局；不应继续沿用用户已经拒绝的普通工作台。

## 5. 多轮搜索与组合

固定已选参考，围绕待确定部分补充下一轮。形成清楚的组合关系，例如场景来自 21/22、浮窗来自 27/28、材质与运镜来自 13/17/18。最终是一套原创、统一的界面，而不是把来源卡片直接贴在一起。

建立配色、字体、间距、容器、材质、动效和响应式规格。保留产品所需文案、导航和真实内容结构。

## 6. 出完整稿并接受反馈

生成完整主视图，必要时补充状态或小屏稿。记录使用的提示词、版本和反馈。用户只要求更亮、更暖时，保留已认可的结构，改变对应轴；用户拒绝结构时则重新构图。

“这套先用”意味着已有授权，不必再次询问是否可以进入下一步。若用户希望两版共存，将它们整理为同一布局的主题，而不是保留两套相互分叉的应用。

## 7. 开发、连接与验收

使用现有框架，代码实现 UI 文案、表单与导航。3D 交互采用真实渲染器，不能用截图冒充。保留原接口、权限、状态、来源、取消／重试与必要业务功能。

在浏览器里比较定稿与实际页面，验证桌面、中等宽度、手机、键盘、减少动态效果、主题持久化和主要流程。区分构建、演示、本地 UI、真实后端与真实用户验证。

## 8. 交付和复用

交付来源清单、决策记录、定稿、提示词／规格、可运行代码和验证结果。开源只打包原创或有再分发授权的资源；业务数据、凭据和私人目录不进入包。

这套流程不是固定风格模板。可以用于聊天、仪表盘、编辑器、品牌网站、内容产品与移动页面；参考数量、轮次和工具按任务调整。
