# Evaluation protocol

Tool regressions and agent behavior are different evidence. CI checks gallery/round/data behavior. The scenarios below specify realistic raw requests and review criteria; they are **not a claim that independent agents or real users passed**.

| Raw request                                                     | A useful result                                                                 | Failure signal                                         |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------ |
| “I cannot explain the style. Find 10–20 pages I can choose.”    | Diverse real sources, stable IDs, clear preview verification, easy reply format | Another arbitrary mockup, or twenty similar dashboards |
| “I like 4/9/12 for their materials. No workbench here appeals.” | Material preference retained; search practical spatial/product layouts next     | Assumes the workbench was accepted                     |
| “Brighter and warmer, keep this structure.”                     | Revised light/palette artifact; structure stays consistent                      | Structural reset or only a prose response              |
| “All drafts are wrong.”                                         | Different structural hypothesis or new reference round                          | Same grid recolored again                              |
| “A compact finance table, keyboard first. No 3D.”               | Dense readable layout, direct actions, useful states                            | Forced immersive scene                                 |
| “Use both variants as themes. Start implementing.”              | Shared structure/theme tokens; proceeds within authorization; browser evidence  | Asks permission again or creates unrelated apps        |
| “Design first; connect the functions later.”                    | Complete concept/prototype before business integration                          | Starts changing backend/credentials                    |
| “Continue from these manifest/choice files.”                    | Reads records, reconciles identity, keeps rejected patterns excluded            | Resets IDs or mistakes favorites for approval          |
| Browser or image generation unavailable                         | Explicit verification limits, useful supported deliverables                     | Invented screenshots or interaction claims             |

For an actual behavioral evaluation, give a fresh session only the raw request, relevant project context and installed skill. Save its output and score observable behavior against these criteria. Do not feed it the intended answer or claim a self-review is independent evaluation. Real-user studies require consenting users and recorded results.

The runnable synthetic rehearsal uses `examples/walkthrough/`: a fictional collection brief, factual choice summary, second-round assembly, gallery build and browser import. It tests reproducibility and decision preservation, not whether a person likes the final design.
